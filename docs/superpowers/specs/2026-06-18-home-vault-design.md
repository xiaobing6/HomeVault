# HomeVault 家庭物品管理系统设计

日期：2026-06-18

状态：已与用户逐段确认，等待最终书面审阅

## 目标

HomeVault 是一个家庭自用的物品记录网站，用来弄清楚家里有哪些东西、放在哪里、属于谁、当前状态如何，以及它们曾经如何移动、借出、消耗或退出库存。

第一版面向桌面浏览器，不做移动网页深度适配；未来计划增加微信小程序，但小程序只重做前端界面，复用同一套后端 API、数据库、权限和业务规则。

## 技术栈

- 前端：Vue 3、Vue Router、Pinia、Element Plus。
- 后端：FastAPI、SQLAlchemy 2、Alembic、Pydantic。
- 数据库：第一版使用 SQLite，通过 ORM 和迁移工具保留迁移到 MySQL 的可能性。
- 认证：token-based 架构，第一版只做账号密码登录。
- 图片与附件：上传到后端文件目录，数据库保存路径和元数据。
- 自动化测试：后端接口测试配合真实浏览器验收测试；浏览器自动化优先使用 Playwright 技能推荐的 `playwright-cli` wrapper。

## 整体架构

系统采用前后端分离。

前端负责桌面端交互体验，包括物品卡片、表格视图、搜索筛选、住宅/位置树、分类字段配置、用户和权限管理、日志查看。界面风格应温馨、清爽、有家庭感，同时保留管理系统的效率。

后端负责认证、权限、业务规则、图片/附件上传、日志、数据库读写。所有核心业务能力都通过 API 暴露，为未来微信小程序复用做准备。

系统按模块拆分：

- 家庭空间：描述一个家庭资产空间。
- 住宅与位置：管理多处住宅，以及每处住宅下完全自定义的位置树。
- 物品库存：管理物品、图片、数量、状态、归属人、保管人、容器关系、流转历史。
- 分类与字段：多级分类树，每个分类定义自己的属性字段和选项。
- 成员与账号：家庭成员是业务身份，登录账号是系统身份，二者可以关联也可以不关联。
- 权限与认证：token-based 登录，角色可变，后端按权限点控制。
- 日志与提醒：全局操作日志、数量变化历史、站内到期提醒和筛选。

## 数据模型

核心表建议如下：

- `home_spaces`：家庭空间，记录家的名称、描述和基础信息。第一版只有一个家庭空间，但结构上预留扩展。
- `residences`：住宅，如现在住处、老家一处、老家二处。包含名称、描述、地址/位置信息、备注、启用状态。
- `location_nodes`：位置树节点。包含所属住宅、父节点、名称、类型/图标、排序、备注。层级完全自定义，不固定房间、柜子、抽屉。
- `family_members`：家庭成员/归属人名单。可关联登录账号，也可不关联。用于物品归属人和当前保管人。
- `users`：登录账号。账号由管理员创建，不开放注册。
- `roles`、`permissions`、`user_roles`、`role_permissions`：角色与权限点。账号和角色不绑死，角色可调整。
- `external_identities`：预留未来微信身份绑定，如 openid/unionid 绑定到后台创建的家庭账号。
- `categories`：多级分类树。物品选择一个主分类。
- `attribute_definitions`：分类下的自定义字段定义，包括字段名、字段类型、是否必填、是否可筛选、排序、默认值、隐私等级。
- `attribute_options`：单选/多选字段的选项，也可支持部分可配置字典。
- `items`：物品主表。包含名称、分类、状态、数量、单位、归属人、当前保管人、当前位置、所在容器、是否容器、隐私等级、软删除标记等。
- `item_attribute_values`：物品自定义属性值。按字段定义存值，不把属性写死到物品表。
- `item_images`、`item_attachments`：物品图片和附件，主图与多图分开标记，数据库存路径和元数据。
- `tags`、`item_tags`：标签。
- `item_movements`：流转历史，记录住宅、位置、容器、状态变化，支持可选原因备注。
- `item_quantity_changes`：数量变化历史，记录变更前数量、变更后数量、变化值、单位、原因、操作人、时间。
- `item_loans`：借出记录，记录借给谁、联系方式、预计归还日期、归还时间、归还位置、备注。
- `audit_logs`：全局操作日志，覆盖登录、登出、增删改、配置变更、权限变更等。
- `reminders` 或提醒字段索引：服务站内即将到期、已过期筛选，不做外部推送。

关键数据规则：

- 物品要么直接放在位置节点，要么放进容器物品，二者互斥。
- 容器本身也是物品，可以放在位置或上级容器里。
- 容器嵌套需要限制最大层级，并防止循环引用。
- 容器的位置变化后，容器内物品的实际位置通过查询继承容器位置，不逐条改写子物品位置。
- 已丢弃、已送人、已出售、已遗失等状态可以没有当前位置，但必须保留历史。
- 重要数据使用软删除、归档或停用，不直接物理删除。
- 管理员修改字段定义时，不直接删除已有字段值；字段可以停用，历史仍可查看。

## 自定义属性

物品属性按分类定义，所有分类共享少量基础字段。第一版支持这些字段类型：

- 文本
- 长文本
- 数字
- 金额
- 日期
- 日期时间
- 单选
- 多选
- 开关
- 链接
- 附件引用
- 加密文本
- 提醒日期

推荐默认字段模板包括：

- 数量和单位
- 购买日期、来源、价格
- 重要程度
- 隐私等级
- 保养/检查提醒
- 有效期/消耗提醒
- 保修到期提醒
- 购买链接
- 存放条件，如防潮、避光、冷藏、易碎、危险品
- 说明书、发票、保修卡、合同扫描件
- 序列号、资产编号、证件号等标识码
- 价值/估值
- 标签

这些字段不是硬编码到所有物品上，而是作为管理员可配置的分类字段和默认模板。

## 状态、移动、借出与数量

物品状态内置基础状态，但管理员可以启用、停用、改显示名称、增加状态。状态需要保留系统语义，例如是否仍在库存、是否需要位置、是否代表退出库存。

基础状态包括：

- 在库/在家中
- 借出/外借
- 已丢弃
- 已送人
- 已出售
- 已遗失
- 已消耗完

移动位置、状态变化、容器变化都写入流转历史。移动原因/备注可填但不必填。

借出是轻量流程：

- 状态改为借出时，填写借给谁。
- 联系方式、预计归还日期、备注可选但推荐。
- 归还时选择恢复到哪个位置或容器。
- 借出和归还都写入流转历史与全局操作日志。

数量变化必须通过专门接口记录历史，不静默覆盖。数量历史记录变更前后、变化值、单位、原因、操作人和时间。

## 前端页面

整体布局为左侧导航、顶部搜索/筛选、右侧内容区。第一版桌面浏览器优先，不做移动网页深度适配。

主要页面：

- 登录页：账号密码登录。
- 仪表盘：物品总数、各住宅物品数、即将到期提醒、最近移动、最近新增、借出未归还。
- 物品页：核心页面。左侧可切换住宅位置树/分类树，右侧默认卡片视图，可切换表格视图。
- 物品详情页：主图、多图、基础信息、自定义属性、附件、位置/容器、数量历史、流转历史、借出记录、相关操作日志。
- 新增/编辑物品：先选分类，再动态显示该分类字段。支持上传主图和附图，选择归属人、保管人、状态、位置或容器。
- 住宅与位置：管理员维护多处住宅和位置树；普通编辑者可查看位置树。
- 分类与字段：管理员维护分类树、自定义字段、选项、字段类型、必填、可筛选、隐私等级。
- 成员与用户：管理员维护家庭成员、登录账号、角色分配、账号启停。
- 状态与字典：管理员维护物品状态、重要程度、存放条件、单位等选项。
- 借出管理：查看借出未归还、即将到期、已归还记录。
- 提醒中心：站内查看保修到期、有效期、检查/保养提醒。
- 操作日志：管理员查看全局日志。

物品卡片默认显示：

- 主图
- 名称
- 分类
- 当前状态
- 所属住宅/位置或容器
- 归属人或公用
- 数量和单位
- 重要/隐私标记
- 即将到期提醒标记
- 标签

视觉风格：

- 暖白或浅米色背景，搭配柔和绿色、浅蓝或暖橙作为强调色。
- 物品卡片像家庭收纳卡，图片清晰，信息层级明确。
- 用直观图标辅助住宅、位置、箱子、证件、工具、药品等识别。
- 默认体验温和舒适，表格视图保留管理效率。

## 认证、权限与安全

第一版只做网页端账号密码登录，不开放注册。账号由管理员创建。

认证采用 token-based 架构：

- 登录成功后，后端签发短期访问 token。
- 前端请求 API 时携带 token。
- 后端每次请求根据 token 找到当前用户，并实时查询账号状态、角色和权限。
- token 中只放最小信息，如用户 ID、会话 ID、过期时间。
- 后端保留会话/刷新记录，便于强制退出、停用账号、改密码后失效。
- 密码使用成熟哈希算法保存，不保存明文密码。

权限采用 RBAC：

- 用户和角色通过关联表连接，角色可以随时调整。
- 角色和权限点通过关联表连接。
- 第一版内置管理员、编辑者、查看者。
- 权限点包括查看物品、新增物品、编辑物品、软删除/归档物品、管理分类字段、管理住宅位置、管理成员用户、查看日志、管理字典等。
- 前端根据权限隐藏菜单和按钮。
- 后端对每个接口再次校验权限，防止绕过前端。

未来微信小程序预留：

- `external_identities` 表保存微信身份绑定。
- 未来微信登录后，用 openid/unionid 绑定管理员已创建的家庭账号。
- 小程序复用同一套物品、住宅、位置、权限、图片、日志 API。
- 第一版不实现微信登录和小程序页面。

隐私与敏感信息：

- 支持普通和敏感两类隐私等级；敏感信息第一版至少做到仅管理员可见。
- 加密文本字段用于证件号、序列号、重要合同编号等敏感内容。
- 重要操作写入全局日志。

## 后端 API 与错误处理

后端按模块提供 REST API：

- 认证：登录、刷新 token、退出、当前用户信息、修改密码。
- 用户与成员：账号、角色、权限、家庭成员、账号与成员关联。
- 住宅与位置：住宅增删改查、位置树增删改查、排序、停用。
- 分类与字段：分类树、字段定义、字段选项、字段启停。
- 物品：列表、详情、新增、编辑、软删除、状态变更、位置/容器变更。
- 图片附件：上传、设为主图、删除/归档、下载/预览。
- 借出归还：创建借出记录、归还、逾期筛选。
- 数量历史：调整数量、查看数量变化记录。
- 提醒：即将到期、已过期、按类型筛选。
- 日志：全局操作日志查询。

错误处理规则：

- API 保留结构化错误类型，便于前端判断。
- 前端页面只显示明确中文提示，不直接显示错误码。
- 未登录提示“请先登录”。
- 无权限提示“你没有权限执行此操作”或更具体的中文说明。
- 字段校验失败提示具体字段和原因。
- 容器循环提示“这个容器不能放进自己或自己的下级容器中”。
- 上传图片限制大小和类型，失败时显示明确原因。
- 重要写操作使用事务，避免部分保存成功导致数据不一致。

## 测试策略

第一版需要自动化测试和手工验收结合。

后端测试：

- 认证与权限：登录、token 失效、角色变更、无权限访问。
- 住宅与位置树：增删改查、排序、停用、层级查询。
- 分类与字段：字段类型校验、必填校验、选项合法性、字段停用。
- 物品：新增、编辑、软删除、详情、搜索筛选。
- 容器规则：互斥位置、嵌套深度、防循环。
- 状态流转：在库、借出、归还、丢弃、送人、出售、遗失。
- 数量历史：数量调整必须产生历史记录。
- 借出归还：借出信息、预计归还、归还位置。
- 日志：登录、登出、关键增删改、配置变更、权限变更。
- 数据迁移：Alembic 能从空库创建完整结构。

前端测试：

- 登录成功和失败。
- 不同角色看到不同菜单和按钮。
- 查看者无法看到或触发管理操作。
- 管理员可以维护住宅、位置、分类字段、成员用户。
- 新增物品时按分类动态展示字段。
- 物品卡片、详情、图片上传、筛选搜索可用。
- 借出、归还、数量调整、状态变更流程可用。
- 页面错误提示显示中文，不显示错误码。

Playwright 自动化验收：

- 使用 Playwright 技能推荐的 `playwright-cli` wrapper 驱动真实浏览器。
- 主要覆盖端到端关键路径，不替代后端单元测试。
- 验收流程包括管理员登录、创建住宅和位置、创建分类字段、创建家庭成员、创建编辑者账号、录入带图片的物品、筛选搜索、借出归还、数量调整、查看日志。
- 权限流程包括编辑者不能进入管理员配置页、查看者不能修改物品、直接访问无权限页面时显示中文无权限提示。
- 截图、trace 等产物放在 `output/playwright/`，不新增其他顶层产物目录。
- 后续如果需要纳入持续集成，再评估是否增加正式 Playwright 测试文件；第一版设计先以真实浏览器验收自动化为目标。

手工验收：

- 使用三个真实住宅样例。
- 使用几类真实物品样例，如证件、家电、工具、药品、收纳箱。
- 使用多个家庭成员样例，包括无登录账号的成员。
- 覆盖物品从住宅一移动到住宅二、放入容器、借出、归还、丢弃后保留历史。

## 第一版不做

- 微信小程序页面。
- 微信登录。
- 二维码或扫码。
- 短信、邮件、微信推送。
- 手机网页专门适配。
- 多家庭 SaaS 化。
- 复杂审批流程。

## 开发阶段建议

1. 基础底座：项目结构、数据库迁移、登录认证、角色权限、初始管理员、全局错误处理、基础布局。
2. 核心资料配置：家庭空间、住宅、位置树、家庭成员、分类树、自定义字段、状态/字典配置。
3. 物品闭环：物品新增编辑、图片上传、卡片列表、详情页、搜索筛选、位置/容器、状态流转、借出归还、数量历史。
4. 管理增强：提醒中心、操作日志、权限页面细化、软删除/停用体验。

导入导出、二维码、小程序、外部通知等能力作为后续版本考虑。
